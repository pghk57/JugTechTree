# 008-技術木DBの辺テーブルの分割
2026/11/13
更新 : 2026/11/20
## 状況（Status）
提案中

## 状況（Context）
- 技術木のDB設計をするにあたり、2種類の辺の扱いについて決める必要が出てきた

## 決定（Decision）
- 辺に関するテーブルを3つ分けて管理することにした
    - required_route_members
        - required_route
    - reqcommended_edges
    - related_edges

## 理由（Reasons）
- 必須・推奨の辺は有効辺であるのに対し関連の辺は無向辺である
- 関連辺の重複を防ぐことや、ADR003のor型の必須の実装をする上では3種類にテーブルを分ける方が都合が良い

## 影響（Consequences）
- 関連辺の重複チェックが楽になる
- 辺の取得時に必須・推奨と関連辺で別々にリクエストをする必要がある
