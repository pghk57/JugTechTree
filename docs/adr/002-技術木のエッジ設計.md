# 002-技術木のエッジ設計
2026/11/07

## 状態（Status）
提案中

## 状況（Context）
- 技術木（ADR001）では、エッジがロードマップの計算と表示に用いられる
- 現在エッジの意味が曖昧であり、このままでは開発に支障をきたす恐れがある
- エッジは次の2種類とする
### 学習順序エッジ（有向）
- 技を学習する上で効果的と思われる習得順序を示す
- 先に学ぶ技を始点として向きをとる
- 経路探索・表示に含める
- 必須と推奨の2段階を定める
    - 必須：理論上終点の技の習得をする上では必要ないが、実質的には始点の技なしには習得が不可能であるという関係
        - e.g. 3ボールのシャワーと4ボールのシャワー
    - 推奨 : 始点の技を習得していると、終点の技の習得の効率が上がる関係
        - e.g. 3ボールのハーフシャワーとリバースカスケード
    - 順序は必須>推奨である
### 関連エッジ
- 習得に直接寄与しないが、関連するまたは参考になる関係
    - e.g. 水平軸と垂直軸それぞれにおけるジェノサイド
- 双方向のエッジであり、経路探索・表示からは除外される
    - データとしては保持する
- ただし、将来的にはノードを選択した際に限り、薄い線で関連技にも線が表示されるようにはしたいと考える
## 理由
- 以前はエッジの意味として「派生元・派生先」を想定していたが、ユーザーにより派生関係の解釈が異なることが部員との議論により発覚
- 理論上全ての技は派生元の技を習得していなくても習得できることもあり、この定義が本質的ではないと判断
- そこで技術木のエッジの意味を「学習上推奨される学習順序」と定義し直し、2種類のエッジを用意することでこれらの問題を解決できると判断
- 人間の主観による評価は順序尺度が限界であると考え、数値による評価は見送った
- 関連エッジは双方向の性質を持つため、そのまま技術木に組み込むとDAGの定義に反する
- このため経路探索や表示からは除外した
## 影響（Consequences）
- エッジを正確に定義することで、技術木の実装に一歩近づいた
- ユーザーにとっても技の関係性が明確になり、利便性が向上すると考えられる
- JTTが提供する技体系はJTTによる独自の解釈とせざるを得なくなった
- 実装設計ではエッジのラベルをどう管理するか考える必要がある
- 学習経路の自動探索アルゴリズムがやや複雑化する
- 技術木の閉路検出には関連エッジを除外する必要が出てきた
- 技のバリエーションの扱い方は別のADRで議論する必要がある
